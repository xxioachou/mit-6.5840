服务器组观察配置是否改变，如果是，就开始转移 shard。
    一个组失去了一个 shard，必须立刻停止对所有相关 key 的请求，并且把对应 shard 的相关数据转移到得到这个 shard 的组。
    一个组得到一个 shard，必须在接受这个 shard 相关的请求之前，接受所有旧主发送过来的这个 shard 的数据。

每个服务器都周期性地 queryConfig()，如果 config 的 Num 改变，并且自己是 Leader，就 Start 一个 re-configuration 操作

Get/Put/Append 操作新增：
    检查是否正在接收 key 对应的 shard 的数据
        是，拒绝操作（ErrWrongGroup）

queryConfig()
    config1 = kv.config
    config2 = new config

    if config1.Num != config2.Num（配置发生改变）
        gid1 = config1.shards[i]
        gid2 = config2.shards[i]

        if gid1 != gid2
            if kv.gid == gid1（当前服务器所在的组失去了 shard i）
                当前 server 是 leader
                    Start() 一个 re-configuration 操作（把k-v对数据放进 Op）

            else if kv.gid == gid2（当前服务器所在的组得到了 shard i）
                标记准备/正在从 gid1 接收 shard i 的数据
            else
                （无事发生） 
    
    kv.config <- config2（如果改变了就会使得当前组立刻拒绝执行所有跟失去 shard 相关的请求）

ReceiveShardData() (RPC)
    过滤接收到的 data，为 gid 对应 shard 的 k-v对存放到本地
    标记从 gid 接收 shard 完毕
    返回成功

execReconfiguration()
    遍历对应 gid 的服务器集合，发送 ReceiveShardData RPC 给 leader 直到成功
